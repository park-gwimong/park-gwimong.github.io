화면에 설명을 붙여야 할 때 "툴팁으로 넣을까 그냥 적어 둘까"에서 자주 멈춘다. 사용법을 알려 준다는 점은 같지만, 설명이 언제 보이는지가 서로 다르다.

이 글은 헷갈릴 때 꺼내 보려고 만든 참고서의 열두 번째 장이다. 여섯 가지를 나란히 놓고, 늘 보이는지 찾을 때만 보이는지와 어느 시점에 필요한 설명인지를 기준으로 구분한다. 툴팁은 [첫 장](/2026/11/26/ux-components-1/)에서 겹쳐 뜨는 컴포넌트로 다뤘고, 여기서는 다른 도움말 수단과 견준다.

## 한눈에 비교

| 이름 | 보이는 때 | 필요한 시점 | 쓰는 때 |
| --- | --- | --- | --- |
| 툴팁 (Tooltip) | 포인터를 올리거나 포커스가 갔을 때 | 조작 직전 | 글자 없는 조작 요소의 짧은 이름 |
| 도움말 텍스트 (Helper text) | 항상 | 입력 전, 입력 중 | 모르면 입력을 틀리는 조건과 형식 |
| 플레이스홀더 (Placeholder) | 칸이 비어 있는 동안 | 입력 전 | 입력 형식의 예시 |
| 코치 마크 (Coach mark) | 자동으로 한 번 | 첫 사용 | 놓치기 쉬운 기능 하나 |
| 투어 (Product tour) | 자동으로, 여러 단계 | 첫 사용 | 화면 여러 곳을 순서대로 안내 |
| 인포 아이콘 (Info icon, Toggletip) | 아이콘을 눌렀을 때 | 궁금할 때 | 일부만 궁금해할 보충 설명 |

인포 아이콘을 눌러 여는 말풍선은 토글팁(Toggletip)이라고 부른다. 툴팁과 생김새는 비슷하지만 호버가 아니라 누르기로 열리고, 다시 누르거나 바깥을 누를 때까지 남는다.

코치 마크는 디자인 시스템마다 이름이 다르다. 스포트라이트, 기능 발견, 티칭 팝오버처럼 부르는 곳도 있고, 여러 단계를 묶은 것까지 코치 마크라고 부르는 곳도 있다. 이 글에서는 한 곳을 한 번 짚는 것을 코치 마크, 여러 곳을 차례로 짚는 것을 투어로 나눈다.

## 고르는 기준

위에서부터 차례로 묻고, 처음 "예"가 나오는 것을 고른다.

1. **모르면 입력을 틀리는 정보인가.** 그렇다면 도움말 텍스트다. 비밀번호 조건처럼 모두가 알아야 하는 내용은 숨기지 않는다.
2. **글자 없는 조작 요소의 이름인가.** 그렇다면 툴팁이다. 아이콘 버튼이 무엇을 하는지 한두 낱말로 알려 준다.
3. **입력 형식의 예시 하나면 되는가.** 그렇다면 플레이스홀더다. 레이블은 칸 밖에 따로 둔다.
4. **일부만 궁금해할 보충 설명인가.** 그렇다면 인포 아이콘이다. 문장이 길어도 되고, 읽는 동안 사라지지 않는다.
5. **처음 보는 사람이 놓칠 기능 하나를 알리는가.** 그렇다면 코치 마크다.
6. **처음 쓰는 사람에게 여러 곳을 순서대로 보여 줘야 하는가.** 그렇다면 투어다.

위에서 아래로 갈수록 사용자가 청하지 않은 설명이 된다. 코치 마크와 투어는 하던 일을 끊고 끼어들므로, 앞의 네 가지로 풀리면 그쪽을 쓴다.

## 자주 틀리는 것

- **플레이스홀더를 레이블 대신 쓴다.** 입력을 시작하면 사라지므로 무엇을 묻는 칸인지 다시 확인할 수 없다. 흐린 색이라 읽기 어렵고, 이미 채워진 칸으로 보이기도 한다. 레이블은 칸 밖에 늘 보이게 둔다.
- **꼭 알아야 할 조건을 툴팁이나 인포 아이콘에 넣는다.** 열어 보지 않은 사람은 틀린 뒤에야 조건을 알게 된다. 모두에게 필요한 내용은 도움말 텍스트로 꺼내 놓는다.
- **인포 아이콘이 호버로만 열린다.** 터치 화면과 키보드에서는 열 방법이 없다. 아이콘을 버튼으로 만들어 포커스가 가게 하고, 누르면 열리게 한다.
- **첫 실행에 긴 투어를 강제한다.** 아직 써 보지 않은 화면의 설명은 기억에 남지 않고, 사용자는 읽지 않고 넘긴다. 건너뛰기를 항상 두고, 가능하면 그 기능을 처음 만나는 순간의 코치 마크로 쪼갠다.
- **도움말 텍스트를 입력 칸과 잇지 않는다.** 눈으로는 붙어 보여도 스크린 리더는 칸에 포커스가 갔을 때 그 설명을 읽지 않는다. `aria-describedby`로 입력 칸과 연결한다.

## 정리

- 먼저 모두에게 필요한 설명인지 묻는다. 그렇다면 늘 보이게 적고, 일부에게만 필요하면 찾을 때 열리게 한다.
- 설명이 필요한 시점에 맞춘다. 입력하는 중에 볼 내용은 칸 옆에, 처음 한 번 알릴 내용은 그 기능을 만나는 자리에 둔다.
- 청하지 않은 설명일수록 흐름을 끊는다. 코치 마크와 투어는 마지막에 고른다.

> 도움말을 고르는 일은 그 설명을 누가 언제 읽어야 하는지 정하는 일이다.
