폼을 만들다 보면 "이 값은 무슨 컴포넌트로 받지"에서 멈춘다. 글이라고 다 텍스트 필드가 아니고, 숫자라고 다 같은 숫자 입력이 아니다.

이 글은 헷갈릴 때 꺼내 보려고 만든 참고서의 여덟 번째 장이다. 여덟 가지를 나란히 놓고, 받으려는 값이 어떤 모양인지와 얼마나 정확해야 하는지를 기준으로 구분한다.

## 한눈에 비교

| 이름 | 값의 모양 | 정확도 | 쓰는 때 |
| --- | --- | --- | --- |
| 텍스트 필드 (Text field) | 자유 텍스트, 한 줄 | 적은 그대로 | 이름이나 제목처럼 한 줄로 끝나는 글 |
| 텍스트 영역 (Textarea) | 자유 텍스트, 여러 줄 | 적은 그대로 | 문의 내용이나 메모처럼 길이를 모르는 글 |
| 검색창 (Search field) | 자유 텍스트, 저장하지 않음 | 대략이어도 됨 | 결과를 찾거나 거르는 말 |
| 자동완성 (Autocomplete, Combobox) | 아는 값 중 하나 | 목록과 일치 | 후보가 많아 다 펼쳐 보일 수 없는 선택 |
| 태그 입력 (Tag input) | 값 여러 개 | 조각 하나가 값 하나 | 받는 사람이나 라벨처럼 개수를 모르는 값 |
| 날짜 선택 (Date picker) | 날짜 | 하루 단위 | 요일이나 앞뒤 날짜를 보고 고르는 날짜 |
| 슬라이더 (Slider) | 범위 안의 숫자 | 대략 | 음량이나 밝기처럼 움직여 보며 맞추는 값 |
| 숫자 스테퍼 (Number stepper) | 숫자 | 정확 | 수량처럼 작은 범위에서 하나씩 바꾸는 값 |

자동완성이라는 말은 여러 뜻으로 쓰인다. 목록에 있는 값만 받는 선택형을 가리키기도 하고, 자유롭게 치는 글에 제안만 붙여 주는 형태를 가리키기도 한다. HTML의 `autocomplete` 속성은 또 다른 것으로, 브라우저가 저장해 둔 주소나 이메일을 채워 주는 기능이다. 이 글에서는 첫 번째 뜻으로 쓴다. WAI-ARIA에서는 이 패턴을 콤보박스(combobox)라고 부른다.

## 고르는 기준

위에서부터 차례로 묻고, 처음 "예"가 나오는 것을 고른다.

1. **저장할 값이 아니라 무언가를 찾는 말인가.** 그렇다면 검색창이다.
2. **날짜인가.** 그렇다면 날짜 선택이다. 다만 생년월일처럼 이미 외우고 있는 날짜는 숫자로 직접 치게 하는 편이 빠르다.
3. **숫자인가.** 한두 단계만 오르내리는 정확한 값이면 숫자 스테퍼, 대략 맞추면 되는 값이면 슬라이더다. 범위가 넓고 정확해야 하면 숫자를 치는 텍스트 필드로 받는다.
4. **한 칸에 값을 여러 개 받는가.** 그렇다면 태그 입력이다.
5. **정해진 후보 중에서 고르는 값이고 후보가 많은가.** 그렇다면 자동완성이다. 후보가 적으면 치게 할 필요 없이 다 보여 주고 고르게 한다.
6. **여러 줄이 될 수 있는 글인가.** 그렇다면 텍스트 영역이다.
7. **나머지는 텍스트 필드다.**

아래로 갈수록 자유롭게 적을 수 있고, 그만큼 틀린 값이 들어올 여지도 커진다. 값의 모양을 좁힐 수 있으면 좁힌 컴포넌트를 쓴다.

## 자주 틀리는 것

- **플레이스홀더를 라벨 대신 쓴다.** 글자를 치기 시작하면 사라지므로 무엇을 적는 칸인지 다시 확인할 수 없다. 옅은 색으로 그리는 경우가 많아 읽기도 어렵다. 라벨은 필드 밖에 늘 보이게 두고, 플레이스홀더에는 형식 예시 정도만 넣는다.
- **정확한 값을 슬라이더로 받는다.** 슬라이더는 손가락이나 포인터로 한 칸 단위를 맞추기 어렵다. 정확한 숫자가 필요하면 숫자를 치게 하거나, 슬라이더 옆에 숫자 필드를 함께 둔다.
- **생년월일을 달력으로만 받는다.** 달력은 보통 오늘 근처에서 열리므로 수십 년 전으로 가려면 여러 번 넘겨야 한다. 이미 아는 날짜는 직접 입력하게 하고, 달력을 쓰더라도 키보드로 치는 길을 막지 않는다.
- **큰 숫자를 스테퍼 버튼으로만 받는다.** 1에서 50으로 가려면 마흔아홉 번 눌러야 한다. 가운데 숫자를 직접 고칠 수 있게 하거나, 범위가 넓으면 숫자 필드로 받는다.
- **자동완성에서 목록에 없는 값을 어떻게 할지 정하지 않는다.** 목록의 값만 받는 것과 새 값도 받는 것은 서로 다른 컴포넌트다. 목록의 값만 받는다면 고르지 않고 필드를 떠났을 때 값이 정해지지 않았다는 것을 알려 준다.

## 정리

- 먼저 값의 모양을 묻는다. 자유로운 글인지, 정해진 값 중 하나인지, 날짜인지, 숫자인지에 따라 컴포넌트가 갈린다.
- 숫자는 정확도로 한 번 더 나눈다. 대략이면 슬라이더, 정확하고 범위가 좁으면 스테퍼, 정확하고 범위가 넓으면 직접 입력이다.
- 고르게 하는 컴포넌트를 쓰더라도 직접 치는 길은 남겨 둔다.

> 입력 컴포넌트를 고르는 일은 틀린 값이 들어올 길을 얼마나 좁힐지 정하는 일이다.
