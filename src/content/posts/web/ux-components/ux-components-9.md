목록에 아직 아무것도 없을 때, 검색에 걸리는 것이 없을 때, 서버가 응답하지 못했을 때 화면은 모두 "내용이 없는" 모습이 된다. 겉은 비슷해도 사용자에게 해야 할 말은 서로 다르다.

이 글은 헷갈릴 때 꺼내 보려고 만든 참고서의 아홉 번째 장이다. 여섯 가지를 나란히 놓고, 누구 쪽에서 생긴 일인지와 다음에 권할 행동이 있는지를 기준으로 구분한다.

## 한눈에 비교

| 이름 | 원인 | 다음 행동 | 쓰는 때 |
| --- | --- | --- | --- |
| 빈 상태 (Empty state) | 없음 | 만들기 | 아직 아무것도 만들지 않은 목록이나 화면 |
| 첫 사용 안내 (First-use, Onboarding empty state) | 없음 | 첫 단계 시작하기 | 처음 들어온 사용자에게 보여 주는 시작 순서 |
| 검색 결과 없음 (No results) | 입력 | 조건 바꾸기 | 검색어나 필터에 맞는 것이 없을 때 |
| 인라인 오류 (Inline error) | 입력 | 그 자리에서 고치기 | 한 필드의 값이 조건에 맞지 않을 때 |
| 오류 페이지 (Error page) | 시스템 | 다시 시도, 돌아가기 | 화면 전체를 보여 줄 수 없을 때 |
| 오프라인 (Offline state) | 연결 | 기다리기, 다시 연결 | 네트워크가 끊겼을 때 |

원인이 "입력"이라는 것은 사용자를 탓한다는 뜻이 아니다. 사용자가 값을 바꾸면 풀린다는 뜻이다.

빈 상태라는 말은 넓게도 좁게도 쓰인다. 넓게는 첫 사용, 검색 결과 없음, 오류까지 내용이 없는 화면 전부를 가리킨다. 이 글에서는 좁은 뜻, 곧 잘못된 것 없이 아직 내용이 없을 뿐인 경우만 빈 상태라고 부른다.

오류 페이지 가운데 404는 원인이 조금 다르다. 시스템이 고장 난 것이 아니라 주소가 틀렸거나 페이지가 없어진 경우다. 그래도 보여 줄 것은 같다. 무슨 일인지와 돌아갈 길이다.

## 고르는 기준

위에서부터 차례로 묻고, 처음 "예"가 나오는 것을 고른다.

1. **네트워크가 끊겼는가.** 그렇다면 오프라인이다. 이미 받은 내용은 지우지 않는다.
2. **시스템이 요청을 처리하지 못해 화면 전체를 보여 줄 수 없는가.** 그렇다면 오류 페이지다. 화면의 일부만 실패했다면 그 부분에만 알린다.
3. **폼의 한 필드에 넣은 값 때문인가.** 그렇다면 인라인 오류다.
4. **검색어나 필터 때문에 비었는가.** 그렇다면 검색 결과 없음이다.
5. **처음 들어온 사용자인가.** 그렇다면 첫 사용 안내다.
6. **나머지는 빈 상태다.**

위쪽일수록 사용자가 스스로 풀 수 없는 문제다. 그럴수록 무슨 일인지 먼저 말하고, 아래쪽일수록 다음에 누를 곳을 앞세운다.

## 자주 틀리는 것

- **빈 상태와 검색 결과 없음을 같은 화면으로 쓴다.** 필터에 걸린 것이 없을 뿐인데 "아직 항목이 없습니다"가 나오면 사용자는 데이터가 사라진 줄 안다. 조건 때문에 비었을 때는 넣은 조건을 보여 주고 지우는 버튼을 준다.
- **불러오지 못한 것을 빈 상태로 보여 준다.** "없다"와 "가져오지 못했다"는 다른 말이다. 실패했는데 "항목이 없습니다"라고 적으면 틀린 정보를 주게 된다. 없음, 불러오는 중, 실패를 따로 그린다.
- **인라인 오류를 색으로만 알린다.** 빨간 테두리만으로는 색을 구분하기 어려운 사용자가 알아채지 못한다. 글과 아이콘을 함께 쓴다. 메시지는 `aria-describedby`로 필드와 잇고 필드에 `aria-invalid`를 붙여 스크린 리더도 읽게 한다.
- **무엇이 틀렸는지만 말하고 고치는 법을 말하지 않는다.** "잘못된 입력입니다"만으로는 무엇을 바꿔야 하는지 알 수 없다. "8자 이상으로 적어 주세요"처럼 맞는 조건을 적는다.
- **오류 페이지에 코드와 내부 메시지만 보여 준다.** "500 Internal Server Error"는 사용자가 할 수 있는 일을 알려 주지 않는다. 무슨 일인지 쉬운 말로 적고 다시 시도와 돌아갈 길을 준다. 입력하던 내용이 있었다면 지우지 않는다.

## 정리

- 먼저 왜 비었는지 가른다. 아직 없는 것, 조건에 걸리지 않은 것, 가져오지 못한 것은 서로 다른 화면이다.
- 사용자가 고칠 수 있는 문제면 고칠 자리 가까이에서 방법을 말하고, 고칠 수 없는 문제면 무슨 일인지와 빠져나갈 길을 말한다.
- 어느 경우든 다음에 할 수 있는 행동 하나를 함께 둔다.

> 비어 있거나 잘못된 화면이 할 일은 까닭을 밝히고 다음에 누를 곳을 알려 주는 것이다.
