> 이 글은 2026-10-22에 진행한 블로그 정비 기록이다. 오전에 읽기 환경을 갈아엎고, 점검에서 나온 결함을 고치고, 검색과 시리즈 탐색을 붙인 뒤 `main`에 배포했다.

## 배경 / 발단

글이 158편으로 늘었는데 읽기 환경은 예전 테마 그대로였다. 본문은 좁고, 코드 블록은 밋밋하고, 글 사이를 이동할 방법은 이전·다음 링크뿐이었다. 디자인부터 손대기로 했다가, 점검 단계에서 눈에 안 보이던 결함이 줄줄이 나왔다.

## 문제

1. 한글 본문을 오래 읽어도 피곤하지 않게 만들 수 있는가
2. 검색 엔진과 독자 양쪽에서 사이트가 실제로 어떻게 보이는가
3. 공개 저장소에 작업 일지를 올리면서 민감한 이름이 새지 않게 막을 수 있는가

## 결정 1 — 본문은 폭과 줄바꿈부터 잡는다

글꼴만 바꾸지 않고 읽는 흐름에 영향을 주는 값을 같이 정했다.

| 항목 | 값 |
| --- | --- |
| 본문 글꼴 / 코드 글꼴 | Pretendard / JetBrains Mono |
| 크기 / 줄 간격 | 17px / 1.85 |
| 한 줄 최대 폭 | 740px (한글 약 40자) |
| 줄바꿈 | `word-break: keep-all` |

`keep-all`을 넣으면 한글 단어가 중간에서 끊기지 않는다. 한글 본문에서는 폭 제한보다 이 값이 체감 차이가 컸다.

여기에 코드 블록 복사 버튼, 오른쪽 고정 목차, 읽기 진행 막대, 다크 모드 토글을 붙였다. 다크 모드는 처음에는 시스템 설정을 따르고 사용자가 고른 값을 기억한다.

## 결정 2 — 점검에서 나온 결함은 전부 고친다

디자인을 마친 뒤 사이트 전체를 훑었더니 바로 고쳐야 할 것이 다섯 가지였다.

- **사이트맵이 없었다.** `@astrojs/sitemap`이 설치돼 있었지만 설정에서 빠져 있었다. 최신 3.6.1은 Astro 5와 맞지 않아 빌드가 깨졌고, 그래서 통합이 꺼져 있었던 것이다. 3.2.1로 고정하자 445개 URL이 생성됐다.
- **404 페이지가 없었다.** 깨진 링크로 들어오면 GitHub 기본 화면이 떴다. 안내 문구와 최근 글 5편을 보여 주는 페이지를 추가했다.
- **`math: true`가 남발돼 있었다.** 102편에 켜져 있었지만 실제 수식이 있는 글은 0편이었다. 전부 `false`로 바꿨다. MathJax를 더 이상 불러오지 않고, `$PATH`가 수식으로 깨지던 글도 함께 고쳐졌다.
- **한글 강조가 깨졌다.** `**…)**에서`처럼 닫는 기호 바로 뒤에 한글이 붙으면 CommonMark 규칙 때문에 굵게 처리가 안 되고 별표가 그대로 보인다. 플러그인으로 사이트 전체를 고쳐 19편에서 1편으로 줄였다. 남은 한 편은 C 코드 `(char **)`를 본문에 쓴 글이라 별표가 맞다.
- **초안이 공개됐다.** `draft: true`인 글도 페이지가 생성돼 직접 주소와 사이트맵에 노출됐다. 프로덕션 빌드에서는 제외하도록 고쳤다.

> 설치만 된 통합은 동작하는 통합이 아니다. 결과물(`sitemap-index.xml`)이 실제로 생성되는지 봐야 안다.

## 결정 3 — 검색과 시리즈는 정적으로 푼다

서버를 두지 않는 사이트이므로 빌드 때 색인을 만드는 Pagefind를 골랐다. 한글도 잘 잡혀서 "추적성"을 검색하면 15건이 나온다. 헤더의 돋보기 버튼과 `/` 키로 열린다. 색인은 빌드 때 만들어지므로 `npm run dev`에서는 동작하지 않는다.

시리즈는 frontmatter 값으로 묶고, 글 상단에 "N편 중 M번째"를 표시하고, 시리즈 목록 페이지를 만들었다. 태그가 겹치는 글 3편은 빌드 시점에 계산해 하단에 보여 준다.

## 결정 4 — 민감 정보는 저장소가 아니라 CI가 막는다

저장소가 공개라서 작업 일지에 사내 프로젝트 이름이나 내부 주소가 섞이면 그대로 노출된다. 36편에서 알아볼 수 있는 이름을 가상 이름으로 바꾸고, 재발을 막는 검사를 붙였다.

- `npm run check:content`가 개인 경로, 사설 IP, 외부 Atlassian 주소, 토큰 형태를 검사하고 걸리면 빌드를 막는다.
- 금지어 목록은 저장소에 두지 않는다. 로컬에서는 `.gitignore`에 넣은 파일을, CI에서는 GitHub Secrets를 읽는다.
- 공개 CI 로그에는 걸린 파일과 줄 번호만 찍고 일치한 내용은 찍지 않는다. 일부러 위반을 넣어 걸리는 것까지 확인했다.
- CI는 PR에서도 검사, 타입 체크, 빌드를 돌리고 배포는 `main` 푸시일 때만 한다.

## 의도치 않은 함정

금지어 목록을 CI에서 읽으려면 `SENSITIVE_TERMS` Secret을 등록해야 하는데 배포 때까지 등록하지 못했다. 그래서 첫 배포 로그에 "기본 규칙만 검사합니다"가 떴다. 등록 전까지는 새 글에 실제 이름이 들어가도 CI가 막지 못한다.

또 하나는 Git 이력이다. 파일을 고쳐도 예전 커밋에는 원문이 남는다. 지우려면 이력을 다시 쓰고 강제 푸시해야 하는데, 되돌릴 수 없는 작업이라 보류했다.

## 마무리

배포 후 `/`, `/search/`, `/series/baton/`, `/sitemap-index.xml`, `/robots.txt`가 200으로 응답하고 없는 주소는 404 페이지로 연결되는 것을 확인했다. 정리 전 이름이 검색되지 않는 것도 작업 일지 두 편으로 확인했다.

다음에 할 일은 두 가지다. `SENSITIVE_TERMS` Secret을 등록하고, 이력을 다시 쓸지 결정한다.
